dsh-armory · 设计提案 v1 · issue #14

Skill 启停开关
看板布局方案

目标只有一个：让每个技能像 MCP 一样有一个“模型侧启用 / 禁用”的开关，不想用了就关掉，不必卸载。 数据层已经存在（写 SKILL.md 的 disable-model-invocation），这份提案只解决入口放在哪、长什么样、几个状态怎么反馈。

提案范围：纯前端 + 文案 + 测试

00先看结论

三个落点、一套开关；禁用只影响模型自动加载，手动 /引用 不受影响。

推荐：卡片右下、列表右侧、详情正文顶部三处同源。 开关只在四类可写来源出现（用户级 / 项目级的 .agents/skills 与 .dsh/skills）； 随 DSH 分发、运行时注册、自定义目录保持只读，不画假控件。禁用态在卡片和列表上保留条目，只加一枚「已禁用」徽标与灰显名字，方便随时释放。

05三个落点，做几个？

推荐 A：三处同源。卡片是默认视图，只在详情里给开关会让大多数人多点一步。

方案落点优点 / 代价建议
A · 三处 网格卡片右下 + 列表行右侧 + 详情控制行 默认网格视图也能一键开关；与 MCP 的列表开关观感一致。代价是卡片多一个绝对定位按钮、底栏让 44px。 推荐
B · 两处 列表行 + 详情控制行；网格卡片只显示状态徽标 卡片零改动，风险最低；但网格是默认视图，用户要先切列表或点详情才能关。 次选

  • 建议一起做的两件小事：① 增「已禁用」筛选 chip；② 修 v2.4.9 更新说明里把入口写成「技能看板」的错标（实际在工具裁缝），避免下一个用户照着找不到。

06边界与风险（必须先说）

开关不是“卸载”，也不是“对全局技能做项目级覆盖”。这三条边界要写进界面与说明。

  • 语义：关掉的是“模型自动加载 / 调用”，手动 /引用 仍然可用。MCP 禁用是整条服务器下线，两者不能混着讲。
  • 来源：只有四类可写根。随包、运行时、自定义目录没有开关；这不是漏做，是写入面不可信。
  • 符号链接：技能目录若指向共享位置（如本机大量 .dsh/skills → D:\skilllocker\store），开关会按 realpath 改写源文件，共用同一来源的其他 agent 也会被一起禁用。建议 v1 就在详情里给一行链接警告（需要后端补一个 lstat 链接位）。
  • 重装：市场重装 / 升级技能会整体覆盖 SKILL.md，开关随之丢失。宿主没有独立禁用配置，做不到真正持久；重装后重新关一次即可，界面上要说明。
  • 作用域：不能“同一个全局技能只在本项目禁用”——标志在文件里，没有作用域覆盖层。要做那种效果得另起一套配置，不在本提案范围。
真机复测项（实现后必做）：
① 关掉技能后，下一轮模型目录里确实不再出现它（上下文税归零）；
② 输入框 /name 仍能手动触发；
③ 根目录监听器自动拾取，无需重启 DSH；
④ 项目档切换后，开关写进的是项目自己的 SKILL.md；
⑤ 只读来源点不到任何写入口。

这五条属于宿主行为，前端单测覆盖不了，必须在装好的 DSH 里逐条验。
